Installer Hypotrail avant l'atelier

Faites l'installation au plus tard trois jours avant. Le jour J, il ne reste qu'à créer son étude. Deux options : Codespaces (recommandée, rien à installer) ou en local. Un poste qui fonctionne par binôme suffit.

Pour tous

Il vous faut
  • un compte GitHub (le dépôt hypotrail/hypotrail est public) ;
  • GitHub Copilot (licence de l'entreprise ou individuelle), avec le chat et le mode Agent ;
  • VS Code 1.109 ou plus récent, pour le sélecteur de réponses de l'agent. Le VS Code de Codespaces est toujours à jour.

Option 1 · GitHub Codespaces recommandée

VS Code tourne dans le navigateur ; rien n'est installé sur votre poste.

1. Forker le dépôt

Sur la page du dépôt, github.com/hypotrail/hypotrail : Fork, puis Create fork (lien direct : https://github.com/hypotrail/hypotrail/fork), sous votre compte personnel. Gardez « Copy the main branch only » coché.

Le fork est votre propre copie : vos études n'y touchent pas le dépôt d'origine, et le codespace est rattaché à votre compte.

Bon à savoir

Le codespace d'un fork personnel utilise le quota gratuit de votre compte : 120 heures-cœur par mois, soit 30 heures sur une machine à 4 cœurs, largement assez pour l'atelier.

2. Créer le codespace (avant l'atelier)

  1. Sur la page de votre fork : Code, puis Codespaces, puis …, puis New with options.
  2. Choisissez la branche main, la région la plus proche (Europe West) et une machine 4-core, puis Create codespace.
  3. Attendez la fin du terminal « Configuring codespace » : 4 à 6 minutes la première fois. Il installe l'environnement du moteur et le panneau d'étude.
  4. Passez le délai d'inactivité à 60 minutes : github.com/settings/codespaces, Default idle timeout.

Le jour J, il suffit de rouvrir ce codespace depuis github.com/codespaces.

3. Vérifier (avant l'atelier)

bash scripts/workshop/new-mpg-study.sh essai --open

Puis passez à la vérification commune.

Option 2 · En local

1. Prérequis

SystèmeÀ faire
LinuxRien de particulier.
macOSInstaller la commande code : dans VS Code, ouvrir la palette, puis Shell Command: Install 'code' command in PATH.
WindowsLe moteur ne fonctionne pas sous Windows natif. Installez WSL2 (Ubuntu) et l'extension VS Code WSL. Faites toutes les étapes suivantes dans WSL, puis ouvrez VS Code en mode WSL (code . depuis le terminal WSL). Sans droits pour installer WSL2, prenez l'option 1.

Et aussi

  • git ;
  • uv, qui installe lui-même Python 3.13 s'il manque : curl -LsSf https://astral.sh/uv/install.sh | sh, ou brew install uv sous macOS ;
  • Node.js 18 ou plus, seulement pour fabriquer le panneau. Inutile si l'organisateur vous a fourni hypotrail-companion-0.1.0.vsix.

2. Cloner et installer l'environnement

Clonez votre fork (ou le dépôt) dans un chemin sans espaces :

git clone https://github.com/<votre-compte>/hypotrail.git ~/hypotrail
# ou, sans fork : git clone https://github.com/hypotrail/hypotrail.git ~/hypotrail
cd ~/hypotrail
uv sync --project framework --group azureml

L'environnement fait environ 650 Mo sur disque (pandas, scikit-learn, SciPy, Marimo, InterpretML…). Faites cette étape sur un bon réseau.

Derrière un proxy d'entreprise : définissez HTTPS_PROXY et UV_SYSTEM_CERTS=1 avant uv sync, ainsi que UV_DEFAULT_INDEX si l'entreprise a un miroir PyPI.

3. Installer le panneau d'étude

Avec Node
bash scripts/workshop/install-panel.sh
Sans Node, avec le fichier fourni

Dans VS Code : vue Extensions, menu …, puis Install from VSIX…, et choisissez hypotrail-companion-0.1.0.vsix.

Faites ensuite Developer: Reload Window. Pour mettre à jour un panneau déjà installé : bash scripts/workshop/install-panel.sh --force.

Si l'installation est refusée (« extension not allowed »), c'est que la politique de l'entreprise filtre les extensions. Le panneau est optionnel : le chat et le rapport suffisent. Prévenez l'organisateur.

4. Vérifier (avant l'atelier)

Depuis le terminal intégré de VS Code, à la racine du clone :

bash scripts/workshop/new-mpg-study.sh essai --open

Puis passez à la vérification commune.

Vérification commune

  1. La fenêtre VS Code se rouvre sur studies/essai. Si VS Code le demande, faites confiance au dossier.
  2. Ouvrez la palette (Ctrl+Shift+P, ou Cmd+Shift+P sur Mac) et lancez Hypotrail: open the study panel. Le panneau s'affiche.
  3. Ouvrez le chat Copilot (Ctrl+Alt+I), passez en mode Agent et choisissez l'agent hypotrail. Dans Configure Tools, vérifiez que vscode/askQuestions est coché.
  4. Écrivez « On commence ». L'agent lance des commandes uv run … hypotrail et affiche la fiche des données.

La règle de l'agent, visible

Le script installe dans l'étude une règle de l'atelier, un « hook » Copilot écrit dans .github/hooks/hypotrail.json. Elle s'applique avant chaque action de l'agent :

autorisé

Une commande simple du moteur, uv run … hypotrail …. Vous n'avez pas à valider chaque étape de l'étude.

refusé

Toute lecture directe du fichier de données brut (auto-mpg.data). Il contient aussi les lignes du test final, scellées. On regarde les données par le panneau, hypotrail data ou les notebooks, et l'étude compte ces regards.

demandé

Tout le reste, comme d'habitude.

noté

Chaque décision de la règle est écrite dans .github/hooks/hypotrail-hook.log, que l'on regardera ensemble.

Les hooks sont une fonction en préversion de VS Code. Si VS Code vous demande quand même d'autoriser une commande uv run … hypotrail, lisez-la, puis choisissez Allow in this Session. N'utilisez pas « Allow all » : il autoriserait toutes les actions de l'agent, y compris les modifications de fichiers.

Le jour J

git pull
bash scripts/workshop/new-mpg-study.sh binome-XX --from-pdf --open
  • Remplacez XX par votre numéro de binôme.
  • En Codespaces, si l'organisateur annonce une mise à jour, cliquez d'abord sur Sync fork sur la page GitHub de votre fork, puis faites git pull.
  • En local, faites git pull, puis bash scripts/workshop/install-panel.sh --force si le panneau a changé.

Dans le chat, écrivez : « Prépare l'étude à partir de la fiche du PO ».
