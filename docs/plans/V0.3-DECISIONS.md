## WP-F1 Method: nested tuning, variants, model families

- F1.1 A family change is a variant (`{"kind": "family", "family": "ebm" | "hgb"}`) of the `model_variant` decision, not a new decision: the candidate stays linear (default, first), the family counts in the same budget of three, and the choice picks one slot (one family) with one rule. New kinds `tuned` (penalty by nested CV) and `family`; v0.2b kinds kept. Review?
- F1.2 The value becomes `{"variants": [{kind, ..., question}, ...]}`; a v0.2b single value stays valid and is read as one variant (budget 1 used); nothing is rewritten. Variants 2 and 3 run as `fit.variant:2`/`:3` (slot names accepted by `run`); the first keeps `fit.variant` so earlier identities hold. The question is not part of the identity (rewording refits nothing).
- F1.3 The budget counts every distinct variant model ever confirmed (from confirmed proposals), so replacing a variant spends a trial; a fourth is `invalid_value` with `details.budget`. Review?
- F1.4 Nested CV: 3 inner folds (shuffled, seeded 20261020, stratified when possible), metric ROC AUC / MAE, tie = simplest grid value. Grids: logistic C 0.01–100 (5 values), ridge alpha 100–0.01, EBM interactions {0, 3}, boosting max_depth {2, 4}. The inner folds are neither temporal nor duplicate-grouped (affects only the hyperparameter choice; stated in CLI-CONTRACT §14). Review?
- F1.5 EBM settings for speed and determinism: 1 outer bag, 0 inner bags, 500 rounds at learning rate 0.05, `n_jobs=1` (measured about 1 s per fit on 500 rows, 5 s on 30k; the default 14 bags were far too slow for nested CV). Boosting: 100 iterations, no early stopping, OpenMP limited to one thread (an unlimited pool stalled for minutes in the sandbox). Review?
- F1.6 `interpret-core==0.7.3` added as a core dependency (framework pyproject + uv.lock; CONTRIBUTING updated). "Its version in the code fingerprint": the module sources `interpret._version` and `sklearn` (which hold the version strings) are listed in the fingerprint modules of `fit.variant` and `final_test.evaluation`; values also record `versions`.
- F1.7 Selection metric = the fits' per-fold out-of-fold ROC AUC (binary) / MAE (regression), not precision at the rule (the policy's paired bootstrap intervals per variant stay in `comparisons`). Optimism = Tibshirani & Tibshirani (2009) per-fold gap estimate. 1-SE rule per ESL §7.10, simplicity order: linear family, then fewer features, then stronger penalty. Stop advice when every paired per-fold difference is within one standard error of zero, or the budget is used. Review?
- F1.8 The selection is stored in the evaluation's values (`selection`), so the report cites registered numbers; `view.selection` recomputes it live with the budget, and `view.model_families` carries the shortlist (both new view keys, after `trials`).

Interpretability `required` excludes boosting; `preferred` and `none` keep both (EBM listed first in both). A family variant proposed while a flag stands is `data_contingent` in the propose payload.
