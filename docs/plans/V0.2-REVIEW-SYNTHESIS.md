## 3. EDA governance (literature review, amended position)

- Target-related EDA on development rows only; out-of-fold numbers are **development evidence**, only the sealed holdout is final evidence (Ambroise & McLachlan 2002; Cawley & Talbot 2010; ESL §7.10.2).
- Three classes of operations: (a) automatic, no fitted parameters (type parsing, documented code mapping); (b) proposal confirmed in the junior's words, parameters refitted per fold (exclusion, missing strategy, rare-category threshold, caps/winsorising, transforms, target transform, splines); (c) population/legitimacy decisions stated with prediction-time information only, applied to all partitions, preferably before any target look.
- Each decision records the analyses that motivated it and is stamped data-contingent if any used the target.
- Never remove evaluation rows based on the target (André 2022; Kaufman et al. 2012). No resampling outside folds; prefer none (van den Goorbergh et al. 2022).
- Single-feature signal leads only to a legitimacy question, never to a keep-top-k rule.
- Normality checks move to post-fit residual diagnostics (Lumley et al. 2002); target log transform needs smearing correction (Duan 1983).
- Honest multiplicity: question per chart + ledger of **target-involving** looks (disclosure, not alpha correction; no evidence a counter changes novice behaviour), intervals and n on every target chart, permutation null band (~19 shuffles), optional lineup "Is this real?" (Buja et al. 2009; Majumder et al. 2013). All-pairs pairplot and full heatmap only on request, counted as many looks.
