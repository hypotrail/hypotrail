# v0.2 implementation plan (v0.2a then v0.2b)

Owner mandate (2026-10-19): implement v0.2a then v0.2b autonomously to the end; the integrator takes decisions alone and logs them in [V0.2-DECISIONS.md](V0.2-DECISIONS.md) for the owner's final review. Scope sources: [OWNER-DEMO-1-REMARKS.md](../acceptance/OWNER-DEMO-1-REMARKS.md) (R1–R11), [V0.2-REVIEW-SYNTHESIS.md](V0.2-REVIEW-SYNTHESIS.md) (sections 3–5), mockups in [../design/companion-v0.2-mockups/](../design/companion-v0.2-mockups/). This plan supersedes the lot ordering of [V0.2-DEMO-FEEDBACK-PLAN.md](V0.2-DEMO-FEEDBACK-PLAN.md).

Standing rules for every work package (WP):

- Start from the tip of `claude/hypotrail-product-review-yrstzb` (reset a worktree onto it first). Commit after each coherent step; the container can restart.
- Gates before handing back (all green): `python3 scripts/check_layout.py`; the engine pytest line of CONTRIBUTING.md; `node --test clients/vscode-companion/test/*.test.js`; `uv run --project framework python -m pytest -q -p no:cacheprovider clients/vscode-companion/test`. After a payload change, re-capture companion fixtures (`clients/vscode-companion/test/fixtures/capture.py`) and fix drift.
- Never weaken an assertion; a changed expectation is explained in the commit message. New refusal codes and payload keys go into `docs/specs/CLI-CONTRACT.md` (freeze test). Additive schema keys do not bump versions; a changed meaning does.
- Test with temporary studies only; never reset existing study state; legacy two-way-split studies must still load (labelled "no final test").
- Maintained text in English. Every decision the WP takes alone goes into the WP's handback under "Decisions taken".
- No human observation and no Copilot run are part of v0.2 (owner decision); they stay listed as unproven.

## v0.2a — usable by a real junior (Bank, Claude Code)

### Wave A1 (parallel)

**WP-A1 Integrity fixes and audience** — owner: `view.py`, `texts.py`, `cli.py` (help/format only), `cmd_explain.py`, `cmd_evidence.py`, `content/` glossary, `migrate.py` + regenerated case files, `commands.py` init only for `.vscode/settings.json` and `.gitignore`.

- Every message the engine emits to surfaces (`next_action.message`, alerts, health, recap lines) carries `audience: junior|agent`; junior-facing variants written in second person, no command or flag names. Agent instructions keep `audience: agent`. Contract documented.
- Recap must not say "up to date" when artifacts are `not_rendered`; `hypotrail --help` lists every command; `explain`/`evidence --format text` print text.
- Feature availability: per-variable `basis` (`discussed` when the variable is named in the user's words or the restatement, `default_from_case` otherwise); surfaces never label undiscussed variables "Your decision".
- Remove migration/tutorial provenance strings from what surfaces render ("Not described in project.json", sha256 of results.json, doubled labels such as "Unknown unknown", "Scenario assumption available_at_prediction").

**WP-A2 Guided confirmation (R1, R3) + ADR 0005** — owner: `commands.py` (decide paths), new `confirm.py`, `state.py` (mode, basis, concern keys), `records.py`, `preconditions.py`, CLI args for decide/mode.
- Study `mode` (`guided` default; `training` and `express` reserved values, implemented in v0.2b). `hypotrail mode set --user-words` (refuses lowering without words).
- `basis`: add `endorsed` and `restated` (keep `explicit` readable for old studies).
- Guided rule: a reply bound to `--proposal` that is the single open proposal at the current revision is accepted when it is not bare, not negative, not conditional ("oui mais", "d'accord sauf", "yes but", "unless"), not a question. No token-overlap requirement in guided. Policy and conclusion (and model_choice for regression) need a reason (a clause beyond the endorsement, e.g. "parce que", "because", "since", "car", ",", or any content token); refusal code `reason_required`.
- Language: proposals carry structured `value` plus `labels: {en, fr}` restatements; `--lang` on propose; surfaces show the label in the study language (`language` in state, default from first proposal or `init --lang`).
- R3: `decide confirm --agent-concern "<text>"` stored on the confirmation and rendered ("Point raised by the agent … kept by the user"); `decide note --about <decision>` with kind `correction` attaches a later correction without reconfirming; mechanical contradiction check for feature_availability (variable named with exclude/keep words against the value) returns a **warning** in the confirm payload, not a refusal.
- ADR 0005 "Confirmation modes" (guided now, training/express in v0.2b) and contract updates. Tests include the owner's exact sentences.

**WP-A3 Final test sealed at init + ADR 0006** — owner: `data.py`, `exposure.py`, `guard.py`, `activities.py` (split only), new `partition.py`, `commands.py` init only for partition assignment, `case.py` (order declaration).
- At `init`, before any look: assign a sealed final-test partition (default 20 %, stratified on the target; temporal on the last rows when the case declares `order: {column|line, direction}`), deterministic seed recorded in state. Stored as row keys hash + counts.
- Every read path (EDA, fit, preview, data card, evidence, export, notebook view) receives development rows only; a guard test proves no holdout row key reaches any activity input. Holdout gets schema validation only (types, allowed categories, ranges from the case) as pass/fail without values.
- Exposure ledger: init structural inspection recorded on development rows; holdout recorded as `sealed`.
- The `split` decision now splits development rows into training/validation (unchanged UX).
- Legacy studies (no partition) load and show "no final test"; no migration of existing state.
- ADR 0006 "Final test partition" (sealed at init in v0.2a; opening ritual and CV in v0.2b).

Integration A1: integrator merges A3 first (widest), then A2, then A1; resolves `commands.py`/`state.py`/`cli.py` conflicts by union; re-captures fixtures; gates green.
