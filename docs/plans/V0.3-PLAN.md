## 1. Diagnosis

- **The journey is not smooth because of the engine, not only the copy.** The agent hits engine refusals the junior then sees: text that passes `check` is refused by `propose` (`literal_number_in_text`); single-feature scores cannot be cited; a stale revision is returned after the opening confirmation; `check` matches a number to the wrong result by value (R33); diagnostics go stale after the first adoption of the same rule (R34).
- **Confirmation is a lottery.** Lexical endorsement lists plus reason rules produce visible refusals. R27 (owner): paraphrase and reasons only in training mode; in guided mode an endorsement suffices for every decision. R16: interactive choices, recorded with channel `choice`.
- **The agent reads too much.** About 65 tool calls and 60–70k words per study, prompt above 8k words. Payloads are agent-shaped, English, and long; the agent re-explains and sometimes contradicts the engine (R32).
- **The panel duplicates the chat and looks wrong.** Root cause of the visual drift: mockups used a private palette, the implementation uses theme variables; spec §13/§15.1 themselves impose sideways scroll and underlines. Bugs: "train 0" (CV `rowsSeen`, `lib/models/eda.js:286`), raw tokens, clipped labels. R23 (owner): decisions only in chat.
- **The discovery case is incoherent (R31).** Online Shoppers labels a session by its own outcome; the target is known at the moment of prediction. Proposed replacement: Hotel booking demand, Resort Hotel (R38).

## 2. Targets (measured in agentic acceptance)

Per study on the discovery case: ≤ 12 junior turns to conclusion; 0 engine refusals shown to the junior in guided mode; ≤ 4 tool calls per pause; agent prompt ≤ 4k words; every number in chat, HTML and notebook traced by `check`; panel gate green at 3 widths × 3 themes, FR and EN.

## 5. Work packages

### Wave 1

- **WP-A engine correctness.** One number-tracing module used by both `check` and `propose` (a text accepted by one is accepted by the other). Rounding: any display of a registered value rounded to the shown decimals, with percent and percentage-point scaling of shares, matches (the R33 values become regression tests); matching is scope-bound (a number is bound to the result named or in scope, never to the nearest value elsewhere). Single-feature scores and segment counts are citable. Every write returns the post-write revision (the opening confirmation bug). Diagnostics keyed on the effective rule value, so adopting the rule they were computed at keeps them current (R34); the end-of-study "some results are out of date" line is junior-facing only when it matters. `propose` returns `data_contingent` and its reason before the agent presents the proposal (R32). Restated/endorsed classification counts only value/label content words (R25 note).
- **WP-E1 panel narrowing and quick fixes.** Remove the W1/W2 confirm/withdraw UI and W3 "propose this rule" (replaced by "Ask the agent" copy-to-clipboard text); W4–W7 stay. ADR 0004 amendment (narrowing), AGENTS.md whitelist sentence, `check_layout.py` asserts no confirm/withdraw/propose call remains. History newest first (R25). Proposal card read-only: restatement block, effects in words, "Confirming changes nothing already done" when nothing is invalidated, internal revision/ids under Details (R22). CV rows-seen bug ("train 0", `lib/models/eda.js`), split-aware wording, raw tokens mapped to words, "0 / 0" and "no declared range" cells dropped, clipped labels.
- **WP-G discovery case.** `use-cases/hotel-booking/` built like the other cases (`build_case.py`, data, README, case supplement with `labels.fr` and groups): Resort Hotel only, prediction at booking time, cancellation target, temporal final test by arrival date, documented leakage traps (reservation_status and its date, assigned_room_type, booking_changes, days_in_waiting_list; verify each from the paper), capacity share default, sources cited from the paper. Data from the tidytuesday mirror, verified against the paper's published counts. Online Shoppers demoted to an advanced case with the R31 incoherence stated in its README. README, START-HERE, AGENTS.md discovery-case wording updated; acceptance scenarios point to Hotel.

## 6. v0.4 candidates (not scheduled)

- **External benchmark on the CWI controlled suite.** Li et al. (2026), "The Silent Failures in Agentic Data Science", arXiv 2610.14115 (CWI): six controlled failure tests (TF01 class imbalance, TF02 messy formatting, TF03 correlation vs causation, TF04 domain feature engineering, TF05 leakage in feature selection, TF06 wrong metric) and a 15-mode failure taxonomy (FM01–FM15) graded by an LLM judge (κ = 0.62 vs one human on 19 pipelines). Their agents (ReAct, AIDE, MLEvolve on Qwen 4B/27B, Gemini-3.7-flash, plus GPT-5.6 on the suite) fail TF03 and TF05 in every configuration, and leakage modes improve leaderboard rank. Proposal: run the six tests with the same agent alone vs through Hypotrail (hint levels × 5 repeats × 2 arms ≈ 240 agent runs; estimated $100–200 at v0.2 acceptance costs), graded with their judge and with Hypotrail's own ledger. Expected (speculative): gains on TF05, TF06, TF01, partly TF03; none on TF02, TF04. Prerequisites: check that the suite, tasks and judge prompt are released and under which licence (project page trl-lab.github.io/ds-agent-failures, unreachable from the build environment).
- Gaps the same taxonomy exposes: FM07/TF04 domain feature engineering (no engineered features beyond preprocessing), FM14 single evaluation of a stochastic model (seeded, not repeated), FM01 task formulation (left to the human).
