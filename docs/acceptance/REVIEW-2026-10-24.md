## Findings by severity

### Blocking for a release that relies on the guarantee concerned

| Id | Area | Finding |
|---|---|---|
| A1 | runtime | `verify_bundle` checks each file against `predictor_bundle.json`, which is itself not bound to the predictor id. Replacing `payload/model.pkl`, regenerating the expected parity outputs and editing two digests keeps the **same predictor id**; `load_predictor` and `check_parity` pass; the final test then scores the swapped model and binds `evaluated` to the original id; the Azure export carries it. Payload, wheel and lock digests and the parity tolerance (1e300 accepted) are not bound. |
| E1 | compatibility | `mlkit.study.activities` and `fit.py` changed in the library work, and `code_compat` attests only `diag.final_test`. Every result of a study created before (`506180a`) is **not current** at HEAD; a study whose final test was opened can never be current again (`final_test.evaluation` cannot be re-run; the `diag.final_test` attestation never takes effect). `LIBRARIES-V1.md` says the opposite and quotes a wrong digest. |
| B-M1 | export | After a capture of `fit.linear`, confirming another model choice: the final test correctly refuses, but `read_export_source` still says `captured` and `export azureml` packages the **old model** as the selected one. |
| B-M2 | exported project | `materialize` splits lines with `str.splitlines()` (the engine splits on `\n`): a record holding U+2028, form feed or NEL shifts row keys, so a **final-test record enters the development rows** silently and the rebuilt candidate trains on it. |

## What was checked and holds

* No answer text reaches the study logs, state, command outputs, errors or exports; no study
  path, user path or final-test key in any Azure export byte; exports byte-deterministic.
* Canonical JSON v1 matches an independent implementation on 1,500 random values; all
  required refusals hold.
* Concurrency: 40 threads or 6 processes publishing one generation produce exactly one; 4
  concurrent submits produce one attempt; 3 concurrent required handoffs publish exactly one.
* The verifier reads index and commit bytes (not the worktree) and ran nothing from a hostile
  repository configuration (fsmonitor, filters, hooks, textconv, includes, pager).
* The understanding review changes no scientific record; off and coaching never block; a study
  without the extension gives byte-identical `export handoff` output with and without the
  feature.
* Statistics: bootstrap, conformal and risk control agree with independent oracles and
  coverage simulations; determinism across processes and hash seeds.
* A study made by `506180a` is read, rendered, exported and continued by HEAD without error
  (but see E1 on currency); its understanding review stays off.
