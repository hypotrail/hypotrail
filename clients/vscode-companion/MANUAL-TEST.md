# Study panel: manual test in a real VS Code

**Status: not run.** WP-I wrote this checklist where no VS Code is available. Nothing below has been checked in a real VS Code, and no automated test replaces it: the Node tests use a fake `vscode` module, and the Playwright tests use a stub `acquireVsCodeApi` and the fallback theme. It is the stage exit criterion of [the plan, §6](../../docs/plans/COMPANION-ADVANCED-PLAN.md#6-real-vs-code-checklist-wp-i-per-stage) and [ADR 0004](../../docs/decisions/0004-companion-advanced.md). Run it with the owner, once per stage you want to move the default to. Since ADR 0004 decision 13 (2026-10-27) the panel is one page (header, To handle, Since your last visit, Now, the path, the tools as drawers) and has no tabs; the items below name those places. Record the results in `docs/acceptance/runs/companion-<stage>-<date>.md`, one line per item: pass, fail (with what you saw), or not checked.

## Setup

1. `uv sync --project framework --group dev` in the checkout.
2. Make two studies **outside the repository**, in a folder whose path has a space, for example `~/hypotrail studies/`:
   - Bank Marketing: `uv run --project framework hypotrail init --case use-cases/bank-marketing/case.yaml --study "~/hypotrail studies/bank"` (expand `~`), then walk it in the chat (or with the CLI) to the fits and one `policy.evaluate --rule capacity:100`, leaving one proposal open.
   - Auto MPG: the same with `use-cases/auto-mpg/case.yaml`, walked to `evaluate.regression`.
3. Start an Extension Development Host from VS Code 1.90 or later: `HYPOTRAIL_COMPANION_STAGE=<stage> code --extensionDevelopmentPath=<checkout>/clients/vscode-companion "~/hypotrail studies"`. Leave `HYPOTRAIL_COMPANION` unset for item 1.
4. Do every item in Light+, then Dark+, then High Contrast where it says "themes".

## Every stage

1. **Flag off.** "Hypotrail: open the study panel" and the link `vscode://hypotrail-local.hypotrail-companion/result/<any 64 hex>` both show "Companion disabled (feature flag)". Process Explorer shows no new `python` process. Then turn `hypotrail.companion.enabled` on. Later, with the panel open, turn it off in the Settings UI: the panel closes and no further `python` process starts (CR.10).
2. **Untrusted workspace.** In Restricted Mode the command shows "The Hypotrail companion runs the study CLI, so it needs a trusted workspace." and nothing opens.
3. **CSP.** Open the webview developer tools ("Developer: Open Webview Developer Tools"): no Content-Security-Policy violation in the console, after opening every fold and drawer. Note whether VS Code's injected default styles apply (CW.10's open point).
4. **Theme tokens (themes).** Text, muted text, links, badges, warning and error cards, chart marks, and the focus outline are legible in each theme.
5. **The watcher.** Confirm or propose something in the chat (`decide ...` through the agent). The panel refreshes once (the revision in the header moves once), with no flicker loop.
5a. **Currency (CR.1).** On a Bank study made on a *copy* of the case, change one digit of a data row of the dataset: after the next watch event or Refresh, To handle shows "The data or the case changed" and the path shows no result as current, at the same revision. Delete `reports/study.html` and press Refresh: the engine's `currency` moves, the report is shown as not up to date with Regenerate offered, and the checks are read again (HE-3, also run on the real CLI by `test_he3_real_cli.py`).
6a. **Now (WP-A5, NOW-1 to NOW-13, themes).** At every stage the page shows Now in the first screen: the engine's question, its options as plain text, and one button whose label shows the question it copies. With an open proposal it names the decision in words, quotes the restatement, says "In short: ..." (hover it: the recorded value) and "Answer in the chat". No instruction to the assistant ("Show the restatement ...", "the junior's ...") and no raw id (`p_5`, `capacity:100`, a result id) is visible without opening a "Details".
6c. **Lesson style and the one page (themes; spec §4, §6, THEME-1 to THEME-5).** Compare with the mockup `docs/plans/mockups/panel-synthesis-fr.html`. The header stays visible while scrolling; the progress line marks the current step. The path lists every step with its value in words; open a step: its results are folds, each chart with its question, its guided reading and "Show values". Open a few folds and a drawer, then make the agent record something: after the refresh the same folds are open and the focus has not jumped (FOLD-1, FOCUS-1). The header's theme button cycles Auto, Dark, Light; Auto follows the VS Code theme; Dark shows the slate board with paper cards, Light the white board; High Contrast keeps the editor's own colours with no ruling, glow, or chalk texture. In the "more" menu switch English | Français: the page and the engine's texts follow at once, and French punctuation of the panel's own words has a narrow space before ? ! : ;.
6b. **High Contrast (themes).** In Dark High Contrast and Light High Contrast every button, Now's copy button included, has a visible border; a disabled button (from v1: "Regenerate the report and notebook" while a command runs) has a dashed border; status and severity tags are readable. With the OS forced colours (Windows High Contrast), the same holds.
6c. **Narrow panel.** Drag the panel to about 420 px, then 320 px: the pills wrap, each step of the path puts its value under its name below 420 px, tables become cards below 600 px, charts never grow past their container (their text is never scaled up), only the sample, the special rows, the dictionary and the development-versus-final table scroll sideways, and the page itself never scrolls sideways (NAR-1 to NAR-3).
6d. **Open in Marimo (every stage).** In "Your deliverables", "Open in Marimo (read)" opens a terminal named "Hypotrail · marimo run study_generated.py" running `uv run --project <engine>/framework marimo run <study>/notebooks/study_generated.py` (the command shown in the box below the rows), and Marimo opens the app read-only; pressing it again shows the same terminal instead of a second one. "Open in Marimo (edit)" does the same with `marimo edit` for the workbench; edits persist in `notebooks/workbench.py`. Stop each with Ctrl+C; close the terminal and press again: a new terminal starts. In reviewer mode only "(read)" is offered. The study's revision does not move. "Open file" opens the `.py` in the editor. Record the Marimo version shown.
6e. **Error state.** Rename the engine's `framework/.venv` for a moment and press Refresh: the content is replaced by the error card with its next step and "Details from the CLI"; restore it and press Retry: the content comes back.
6. **Keyboard.** Tab reaches every control, in the page's order; Enter or Space opens a fold or a drawer; a link to a place of the page (a To handle item, a chart in the Data drawer) moves the focus to its heading; Escape closes a popover, a tooltip or a modal and returns focus to the opener.

## Stage v1

7. (v0.3, WP-E1) An open proposal in Now is read only: the restatement, the value in words, "What your answer will change" in words ("Confirming changes nothing already done." when nothing is invalidated), "Answer in the chat", and the copy button; no field, no Confirm, no Withdraw. The copy button puts the ready question on the clipboard at once (no modal); paste it in the chat. Confirm in the chat: Now moves on, and the step's history in the path shows the confirmation first, its revision and time on hover.
7b. **Per study (CR.2).** Open a few folds in study A, switch to study B with the "more" menu's study switch: B shows none of A's folds or words.
8. Withdraw a proposal in the chat: Now no longer shows it after the next refresh.
9. Interrupt a run (`HYPOTRAIL_TEST_HOOKS=1 HYPOTRAIL_FAULT=run_after_reserve` on one agent `run`), refresh: "Waiting for your words" and the step in the path show the interruption read only, say that acknowledging it is done in the chat in your words, and offer the copy button; there is no words field, no Acknowledge and no Restart button (R31). Acknowledge it in the chat ("ok" alone is refused there), refresh: the interruption goes away.
10. Regenerate: the report and notebook are rewritten; the deliverables' status follows.
11. Checks of the deliverables (the Deliverables drawer): opening the checks runs `check` once; "Open" on a finding opens the report at its anchor in the browser, or the notebook or workbench at its line in the editor.
12. Study switch: the header's "Study: <name>" lists both studies by folder name and path; choosing the other one opens it **in the same panel**; "Pick another folder..." reaches a study elsewhere.
13. Reviewer mode: "Hypotrail: open the study panel (reviewer, read-only)" shows the badge and no write control (Export excepted from v3).

## Stage v2

14. Slider latency (What if?, Bank): move the slider 10 times; record the median time from release to the updated numbers.
15. EDA: request a distribution of `age` (Bank) and of `weight` (Auto MPG): the chart appears in its step of the path; the ledger line and the exposure ledger gain training rows only. In Bank, `duration` reads "(feature, not available at prediction time)" and still runs on training rows (CR.7).
16. (v0.3, WP-E1) A rule the agent has not evaluated says so and offers "Ask the agent to evaluate"; after the agent evaluates it, the engine's draft appears with "Ask the agent to propose this rule", which copies a question naming the rule in words ("top 150 rows") and its token. Paste it: the agent proposes it in the chat, and Now shows it as proposed in the chat. Rules read in words in the headings and tables.
17. A deep link printed in the chat (`vscode://hypotrail-local.hypotrail-companion/result/<id>?study=<path>`) opens the panel on that result, focused and highlighted; a link naming another study asks with the quick pick. Repeat with a study folder whose name holds `+` and `&` (the path encoded with `encodeURIComponent`): the link opens that study (CR.11).
18. "Show in report" opens the report at `#r-<id>` (check the fragment in the browser's address bar); "Show in the notebook" opens the generated notebook at the line naming the result.
19. "Ask the agent about this": "Copy for the chat" puts the template text on the clipboard; paste it in the chat. "Insert into the chat" is absent even with `chatInsert` set by hand (CR.8). To verify the insertion, a development build sets `CHAT_INSERT_VERIFIED = true` in `lib/flag.js` and `chatInsert` in `settings.json`: "Insert into the chat" must **insert, and not send**, in the Copilot chat. Record the VS Code and chat extension versions; only that record may justify changing the constant.
20. Auto MPG: no block, fold or drawer shows threshold, capacity, precision, recall, positive class, policy, calling rule, decision rule, or selected.
20a. (WP-A7, SAMPLE-1 to SAMPLE-5) At step 1, Now shows the data card: one row's meaning, the development rows and columns, the target, the sealed final test line, the sample of eight seeded development rows (row key, then the target "to predict") with the sentence that these target values are a counted look, and the grouped dictionary; the Data drawer shows the same card. "Show French labels" switches the descriptions to French and back (Bank and Auto MPG). The data card shows no rate of the outcome. `hypotrail data` adds no exposure record beyond the sample's counted look (check the ledger line before and after opening the drawer).
20b. (WP-A7) The quality card says it reads the development rows without the target; each chart is titled by its question; a by-column chart shows a line (interval) and a grey band (shuffled outcome) per group and one sentence about the band; in Bank the leakage detector asks about `duration` and says your decision already leaves it out. "Run another chart" shows the question before you run it, and "one more look" for an outcome-rate chart; after the run, the banner's count of looks goes up by one.
20c. (WP-A7) The confirmation-mode pill of the header opens "What counts as your answer", which names the guided mode and the reason rule and offers no control; a step's history in the path shows restated, endorsed, or delegated chips with their meaning on hover, an agent concern kept on a confirmation (make the agent confirm with `--agent-concern`), and a correction (make the agent record `decide note --kind correction`).
20d. (WP-A7) The header shows "Final test sealed · N rows" at every stage, v0 included; a study created before v0.2a shows "No final test". Now's criterion line shows the success criterion with its status and, once the policy is evaluated, the gain and its interval as in the report.
20e. (WP-B5) Use a new Bank or Online Shoppers study with the engine's cross-validation (the agent's default split), the default variant, and a rule chosen. The final-test step of the path shows "Final test sealed" with its row count, "nobody has read", what must be confirmed first (✓/✗), and "Opening it is a chat act"; there is no button. The ledger explains each purpose in words and marks the final-test rows. A result fold of the model step ("Development evidence · used to choose") says the cross-validation scheme in words, shows the spread across folds (mean ± sd, lowest – highest), and the variant against the candidate (each model, then the paired difference and its sentence). "Final evidence · measured once" says nothing is measured yet.
20f. (WP-B5) Ask the agent to propose opening the final test. Now reads "Open the final test, in the chat" with no button; it has no words field and no "Confirm" (only the copy button). Open it in the chat in your words with a reason. Refresh: the final-test card reads "Final test opened once", the revision and time, your words, and what was measured; the final evidence shows the model against the baseline on the final-test rows and the success criterion judged there, as in the report; Now's criterion line shows the same. Ask the agent to propose opening it again: the refusal reads "already opened" with the revision. Change the rule in the chat: the final-test card lists "Changed after the opening".
20g. (WP-B5) What if?: choose "Share", move the slider (the label reads "Act on the top p of the scored rows"); the gain curve shows the engine's points (5, 10, 20 % and each evaluated rule), the diagonal, "your rule" and, on Online Shoppers or Bank full, "exercise assumption" with the sentence that the share is the exercise's, not a team's. "Try this share" moves the slider and runs only `preview policy`. For a share rule the agent evaluated, "Ask the agent to propose this rule" copies a question (v0.3: the panel proposes nothing); a gain point that was not evaluated says so.
20h. (WP-B5) Ask the agent to switch the mode to training, then express (in your words): the mode pill and Now say what counts as an answer in each mode and that the mode changes in the chat only; no control. In training, a reply that does not restate the proposal is refused with the points not said yet, and no suggested words.
20i. (WP-B5 with WP-B4) Ask the agent to run `diag.binary` (Bank) and, after the opening, `diag.final_test`; and `diag.regression` (Auto MPG). The model step and the final-test step of the path show the diagnostics, development and final evidence apart: the rule in words and its source, the confusion at the rule in words, AUC and average precision, the gain and calibration curves, segments with intervals, the largest coefficients; for Auto MPG the errors, residuals by range of the prediction, the quantile plot, residuals by variable, and no rule words. Before the opening the final part says the final test has no diagnostics yet. No control runs a diagnostic. Compare one number per chart with the report's "Model diagnostics".

## Stage v3

21. Export a handoff pack (the Deliverables drawer): the folder dialog defaults to `<study>/handoff/`; the outcome lists the files and sizes and the warnings in words; "Open folder" reveals the folder the engine reported; exporting again to the same parent is refused verbatim. The engine of this checkout knows `--expected-revision`: make the agent record something between the panel's last refresh and the export: the export is refused as stale (CR.6). With an older engine that does not know the option, the export is refused once, with the engine message verbatim and the sentence that the engine is older than the panel; no pack is written.
22. Learning layer: hover and focus a marked term (the term first, then its definition); "My notions" lists the notions met so far; a concept card collapses after its second full sighting; "Predict before you look" in Now keeps your answer; reload the window: the count and your prediction answers persist; turning `learningLayer` off removes every hover, card, and prediction.
23. `globalState` dump (from a debug console of the extension host, `context.globalState.keys()` and their values): only `hypotrail.learn.prefs`, `hypotrail.learn.seen`, `hypotrail.learn.predictions`, with no path, words, revision, or id.
24. Session report: with the session log on (`HYPOTRAIL_SESSION_LOG=1` for one CLI call), "Session report" shows "Session log: on" and no words. Leave the panel open through a few watch refreshes and an explicit Refresh: `.hypotrail/session-log.jsonl` gains no `status` or `check` line from the panel (its reads run with `HYPOTRAIL_SESSION_LOG=0`); a `hypotrail status` typed in the terminal, and each panel write (a render), does add one; an export adds none.
