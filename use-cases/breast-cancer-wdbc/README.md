# Breast Cancer Wisconsin (Diagnostic)

Third real case, a **binary** study used to test that the engine is not specialised to Bank Marketing (roadmap M3, generality). It is the WDBC dataset as bundled with scikit-learn (`sklearn/datasets/data/breast_cancer.csv`, documented in `sklearn/datasets/descr/breast_cancer.rst`).

## Data are not committed

The scikit-learn package files state no licence or redistribution terms for this data: `breast_cancer.rst` names the creators (Wolberg, Street, Mangasarian, November 1995), the donor, and says it is a copy of the UCI ML dataset, and the scikit-learn licence (`COPYING`, BSD-3-Clause) covers the software. Redistribution from this repository is therefore doubtful, so only the adapter is committed:

- `prepare.py` copies the bundled file from the installed scikit-learn (no download) into `data/wdbc.csv` (ignored by git), with a header of snake_case feature names and the class written as `malignant` or `benign` (the package file codes it 0 and 1; 0 is malignant). Every value is copied as written.
- `case.yaml` ([`hypotrail.case/1`](../../docs/specs/CASE-CONTRACT.md)) is generated by `prepare.py` and committed. `prepare.py --check` fails if a scikit-learn upgrade changes the bundled bytes; the dataset sha256 in `case.yaml` would no longer match, and the engine would refuse the data (`dataset_changed`).

```sh
uv run --project framework python use-cases/breast-cancer-wdbc/prepare.py
uv run --project framework hypotrail init --case use-cases/breast-cancer-wdbc/case.yaml --study /path/outside/the/repository/wdbc-study
```

Tests materialize the case in a temporary folder (`prepare.py --out DIR`), never here.

## Scenario

A pathology service receives more fine needle aspirate (FNA) samples than its senior pathologists can review urgently. When the image of a sample has been analysed, and before the diagnosis, a score ranks the samples so that a limited number of urgent reviews (a capacity) or every sample above a threshold goes first. The positive class is `malignant`.

This is a teaching scenario, not a clinical one: no conclusion from it bears on diagnosis.

## Honest notes

- **Well known to language models.** WDBC is one of the most used teaching datasets. An agent has likely seen analyses of it (near-perfect AUC, the usual "worst" features), and the documentation publishes the class distribution of every row (212 malignant, 357 benign). The case lists both under `prior_exposure`: no row is unseen.
- **Prediction-time semantics are artificial.** All 30 features are computed from the same image, so their availability at the moment of scoring is a scenario assumption, not a documented fact. There is no leaky variable to discover, unlike `duration` in Bank Marketing.
- **No identifier.** The scikit-learn copy has no patient or sample identifier, so whether one patient contributes several images is unknown; the case declares no group column.
- **All features are numeric** with no special value; the case exercises 30 correlated features and a small validation partition (about 171 rows with a 30% split).
