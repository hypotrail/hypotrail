# Diabetes progression

Fourth real case, a **regression** study without a time column, used to test that the engine is not specialised to Auto MPG (roadmap M3, generality). It is the diabetes dataset of Efron, Hastie, Johnstone and Tibshirani (2004), as bundled with scikit-learn (`sklearn/datasets/data/diabetes_data_raw.csv.gz` and `diabetes_target.csv.gz`, documented in `sklearn/datasets/descr/diabetes.rst`).

## Data are not committed

The scikit-learn package files state no licence or redistribution terms for this data: `diabetes.rst` gives the source URL (NCSU) and the reference paper, and the scikit-learn licence (`COPYING`, BSD-3-Clause) covers the software. Redistribution from this repository is therefore doubtful, so only the adapter is committed:

- `prepare.py` copies the **raw** feature file (what `load_diabetes(scaled=False)` returns) and the target from the installed scikit-learn (no download) into `data/diabetes.csv` (ignored by git), with a header. Feature values are copied as written; the target, stored as `1.51e+02`, is written as the integer `151`.
- `case.yaml` ([`hypotrail.case/1`](../../docs/specs/CASE-CONTRACT.md)) is generated by `prepare.py` and committed; `prepare.py --check` detects a change of the bundled bytes.

```sh
uv run --project framework python use-cases/diabetes/prepare.py
uv run --project framework hypotrail init --case use-cases/diabetes/case.yaml --study /path/outside/the/repository/diabetes-study
```

Tests materialize the case in a temporary folder (`prepare.py --out DIR`), never here.

## Scenario

A diabetes clinic wants to plan follow-up visits. At the baseline visit, once its ten measurements are available, it estimates the disease progression score one year later, so that patients expected to progress most are seen first. Errors are reported in the score's own scale, named `points` in the case.

This is a teaching scenario, not a clinical one.

## Honest notes

- **Well known to language models.** The dataset is bundled with scikit-learn and is the running example of the Least Angle Regression paper; an agent has likely seen analyses of it. The case lists this under `prior_exposure`: no row is unseen.
- **Pre-standardised features in the default loader.** `load_diabetes()` returns features that are mean centred and scaled over all 442 rows (`diabetes.rst:31`), which would leak validation rows into the scaling. This case uses the raw values instead (age in years, sex coded 1 and 2); the engine standardises on training rows only.
- **Undocumented units and codes.** Only age has a documented unit. Which sex code is which is not documented (`sex_coding`, status `unknown`); the case declares sex a category, so it is one-hot encoded. `s5` is "possibly" the log of serum triglycerides, in the documentation's own words.
- **Prediction-time semantics are artificial.** "Baseline variables" is documented; that the estimate is made at the baseline visit is a scenario assumption.
- **No time or group column.** The study uses a random split (not stratified: the target is numeric), and the evaluation has no residuals by period.
